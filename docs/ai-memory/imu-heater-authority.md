# 加热片的权限只有 0.28 °C / 1%

## 实测数字

这块板子上,**每 1% 占空比约换到 0.28 °C 的芯片温度**。

所以原来那个从厂商例程抄来的 **5% 上限只给出约 1.4 °C 的权限** —— 根本到不了 40 °C 设定点,
而这不是控制器调不好,是权限不够。

## 怎么确定的

把加热元件**真的断开**再测。结论:静态温度里的大部分其实是 **H7 自身的自热**,不是加热片。
不做这个对照,很容易把自热误当成加热片的效果,从而高估权限。

## 修复后的实测

上限提到 25%,增益从上限反推:

```c
#define IMU_HEATER_DUTY_CAP_PERCENT 25.0f
#define IMU_HEATER_KP (IMU_HEATER_DUTY_CAP_PERCENT / 5.0f)
#define IMU_HEATER_KI (IMU_HEATER_DUTY_CAP_PERCENT / 100.0f)
```

**增益由上限推导而不是独立写死**,这样重新调上限时增益跟着走,不会留下一组和上限不匹配的
增益。

硬件实测:稳态 40.000-40.125 °C,占空比 16.4%,过冲只有一个温度 LSB,**稳态输出完全由积分
项承担**(比例项在稳态趋零,这本身就是"权限够了"的证据)。

另加 `IMU_HEATER_OVERTEMP_C 55.0f` 的过温切断。注意执行顺序:**过温切断跑在 100 周期分频器
之前**,而控制器只在分频器到期时才跑 —— 我写测试时按 `run_body(1u)` 断言过温,失败了,那是
我对执行顺序的误解,不是代码缺陷。

## 仍然不知道的

**加热元件的功率额定值。** 25% 是实测够用的值,不是从元件规格算出来的余量。如果换板子或
换元件,这个数字要重测,不能沿用。

## 怎么应用

`App_Imu_HeaterDutyCap()` 存在的唯一理由是让测试**读这个访问器**而不是硬写 `5.0f` ——
之前正是一个硬写的断言在上限调整后失败,把"重新调参"变成了"顺带改测试"。

暴露一个访问器,让重新调参不会留下过期的断言。厂商例程的周期和上限**都不要照抄** ——
见 [[dm-mc02-vendor-examples]],我们每一个数字都因为一个写下来的理由而不同。
