# 阻塞 SPI 是刻意的,不是没来得及改

## 数字

两次传输共 **17 字节**,SPI2 为 7.5 Mbit/s,线上 **18.1 µs**,在 1000 µs 的周期里
**约 1.8% CPU**。

换成中断驱动要引入回调、状态机,还要和刚补好的那 17 个中断处理器交互
([[cubemx-regeneration-hazards]])。为 1.8% 不值得。

## 一个前提:异步在此之前根本不可能

`SPI2_IRQHandler` 在 2026-08-28 之前是**空的**,任何异步 SPI 传输都会无限重入直到栈耗尽。
现在补好了,所以异步至少是**可能的** —— 但依然不必要。

## 与参考实现对比(2026-09-01)

参考实现在 `/home/stg/Downloads/Gimbal/`。它**也是阻塞的**,而且更慢:

```c
uint8_t BMI088_Read_Write_Byte(uint8_t txdata) {
    uint8_t rxdata = 0;
    HAL_SPI_TransmitReceive(&hspi1, &txdata, &rxdata, 1, 1000);
    return rxdata;
}
```

**逐字节,超时 1000 ms。** 每周期 HAL 调用次数:参考 **16** 次(加速度 1+6、陀螺 1+8)
对我们 **5** 次 —— **3.2 倍**。线上字节数相同,差的全是 HAL 每次调用的参数校验与状态机开销。

超时也是实质差别:**1 kHz 循环里 1000 ms 超时**意味着一次总线故障阻塞任务整整一秒 =
1000 个周期。我们是 `SPI_TIMEOUT 10u`。

## 参考实现里一个偶然正确的缺陷

`BMI088_Accel_Read_Multi_Reg` 宏发一次地址,然后调 `BMI088_Read_Multi_Reg`,**里面又发一次
地址**。结果偶然是对的:加速度计读需要"地址 + 1 dummy + 数据",重复的地址字节正好占了 dummy
的位置。但理由是错的 —— 它不是有意发 dummy,是宏嵌套重复了。陀螺宏没有那层重复,而陀螺**不
需要** dummy,所以两个宏不对称,而不对称恰好补偿了两个 die 的差异。**能跑,但没人写下为什么。**

我们把它做成显式参数 `reg_read(spi, reg, dst, len, dummy)`,注释记录了代价:legacy 驱动两个
die 走同一条路径都不丢 dummy,结果**加速度计每个样本错位一个字节 —— 陀螺正常、加速度计不正常**,
这是最难查的那类症状。

## 总线仲裁:我们必须有,参考不必

参考实现用宏直接翻转 GPIO,没有总线所有权概念 —— 它能这样是因为 **hspi1 上只有 BMI088**。

我们两个 die 共用 `hspi2`,而原来"持有 CS"跨越一次事务、"仲裁"只跨越一次传输,另一个设备
可以在同一事务的两次传输之间抢到总线 → **两个片选同时为低、两个 die 同时驱动 MISO**,数据
错误且无任何报错。修法是让 `cs_assert` 取走总线锁并返回 `bool`。

## 怎么应用

**"阻塞"本身不是缺陷,先算它占多少。** 1.8% 的东西不值得换成状态机;真正值得看的是超时值
和总线仲裁,那两个才是会咬人的。
