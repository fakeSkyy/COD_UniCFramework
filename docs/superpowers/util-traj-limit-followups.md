## 唯一的未完成验收项：上板验证

本模块**没有任何调用者**，所以 `--gc-sections` 把它整个从镜像里丢掉了（`arm-none-eabi-nm build/COD_UniFramework_H7.elf | grep -i trajlimit` 为空，这是预期的）。除编译和 host 测试外没有任何验证，而这台机器没接调试探针，上板验证当时也不可行。

接第一个调用者的人需要做两件事：

1. **核对浮点分辨率下限**。头文件里的判据是

       a_max * dt² >= |pos| * 2⁻²³

   注意是 `|pos|` 而不是 `|target|` —— 用真实坐标量级代进去。云台按 deg（±180）没问题；如果坐标是 mm 或编码器计数这类大数值，余量会迅速变薄。不满足时的症状是**位置冻住**而速率照报，不是速率发散 —— 找错症状会浪费很多时间。

2. **决定能否接受被迫的越过**。从静止接近目标不过冲（实测精确为 0）。但目标移到**已在运动的输出身后**时，越过是加速度上限物理强制的：`v_max = 500`、`a_max = 2000` 下从巡航速度掉头要 250 步、62.25 单位行程。不能容忍的调用方必须自己限制目标的变化率。曾有一段位置夹紧试图掩盖这件事，它伪造了速率产生不出来的位置，已删除。

## 这个模块的历史值得读一遍

`Step` 有过**五个版本**，前四个都是缺陷，而且**没有一个是靠阅读代码发现的** —— 全部来自对抗性测量。完整过程在 `docs/superpowers/specs/2026-08-21-util-traj-limit-design.md`。

给这个模块改代码或加测试前，请先读那份 spec 里的两节：

- **「这个算法经过三次修正才对」** 和 **「第五次修正」** —— 每一版失败的具体原因。
- **「覆盖率不证明断言」** —— 全程保持 100% 行 + 分支 + 双向分支覆盖，五个缺陷一个都没抓到。

三条具体的坑，都在这个模块里各自出现过不止一次：

1. **在错的变量上断言上限。** 第三版在 `vel` 上守住了加速度上限而 `pos` 是错的；第四版的位置夹紧同样如此。所有基于速率的断言都通过了。现在有一条测试断言**交付位置的差分等于报告的速率乘 dt**，那正是缺陷藏身的缝隙 —— 不要删它。
2. **`Reset` 之后实例平凡地"已落定"。** `while (!IsSettled(...))` 的循环体一次都不会跑。这个错误在本模块里出现过三次（含我自己的验证程序）。等待条件的循环一律 `do/while`，先 `Step` 后判断。
3. **「没测出反例」不等于「路径不可达」。** 有过两次把活代码判成死代码的近失，一次靠更宽的随机化推翻，一次靠发现自己的代数证明用错了前提。
