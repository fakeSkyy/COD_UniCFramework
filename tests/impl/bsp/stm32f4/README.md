# STM32F4 backend host tests

These ten Unity executables compile the real `04_impl/bsp/stm32f4` translation units against a minimal, F4-specific host HAL contract. HAL and `IMPL_malloc`/`IMPL_free` are generated by the vendored official CMock 2.7.0; `util_registry.c` is linked as production code so interrupt routing is exercised rather than replaced. The tenth executable builds UART with registered HAL callbacks. It captures the HAL-accepted RX, TX, and error thunks, routes them through real user callbacks, executes every thunk in all eight production slots, and checks each registration rollback step plus ninth-context rejection. The normal weak-symbol suite separately covers unknown handles, late events, missing user callbacks, and errors while reception is stopped.

Run everything with `./tests/run_tests.sh /tmp/COD_UniCFramework-build-stm32f4`, or run only this group with `ctest --test-dir /tmp/COD_UniCFramework-build-stm32f4 -L stm32f4 --output-on-failure`.

Generate a disposable copy with `./tests/scripts/cmock/generate.sh --domain impl-stm32f4 --output /tmp/cod-cmock-stm32f4`, and verify it with `./tests/scripts/cmock/check.sh`. The manifest keeps F4 on its dedicated inline CMock driver rather than silently replacing its options with another domain's YAML. Ruby resolution is `RUBY`, then `CMOCK_RUBY_ROOT`, then `ruby3.2`, then `ruby`; committed files change only through the checker's explicit `--update` option. Every suite initializes both generated mocks and verifies both before destroying either one. Official CMock 2.7 strict ordering remains enabled.

Cases that exercise append-only backend registries or the static Flash region pool run as separate CTest processes. Each case therefore creates its own contexts and cannot inherit route capacity, bus ownership, or Flash regions from a preceding case. Registered-callback UART cases also carry the `register` label; a failed slot is exercised before and after reuse so an old thunk cannot retain a freed context or misroute once the slot has a new owner.

Flash tests map only the emulated F407 flash window with `MAP_FIXED`; run them on a Linux host where `0x08000000` is available. The HAL callbacks update this private anonymous mapping.

The F4 SPI backend now implements the `SPI_Ops_s.cs_assert` production contract rather than hiding the old function-pointer mismatch: assertion returns `bool`, claims the shared bus, is idempotent for its owner, rejects a competing device, and keeps both CS and bus ownership across repeated blocking or asynchronous transfers until the owner deasserts. A non-owner/no-hold deassert is inert. The F4 implementation intentionally retains its own HAL and memory behavior and does not copy H7 cache-maintenance logic.
