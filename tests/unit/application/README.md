# 01_application host tests

These suites compile the six production `01_application` translation units directly on the host and replace only their dependency boundaries with mocks generated by the repository's official CMock 2.7.0 copy.

`case_runner.h` runs one Unity case per process. This isolates file-static production state while retaining normal Unity failure reporting. CTest registers every case separately with labels `application;unit;cmock`.

The board suite also compiles the real `board_devices.def`. Files under `host/` shadow only CubeMX and STM32 binding headers and provide the vendor globals needed to link `board_devices.c`; they are never part of firmware builds.

Run all host tests with:

```sh
./tests/run_tests.sh /tmp/COD_UniCFramework-build-application
```

Run only this group after configuring/building with:

```sh
ctest --test-dir /tmp/COD_UniCFramework-build-application -L application --output-on-failure
```

Generate a temporary copy with `tests/scripts/cmock/generate.sh --domain unit-application --output /tmp/cod-cmock-unit-application`, then verify all committed domains with `tests/scripts/cmock/check.sh`. Use the checker's explicit `--update` option only when intentionally refreshing committed mocks. The domain configuration enforces strict call ordering; generated files under `mocks/` must not be edited by hand.
